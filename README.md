# 紫微斗數 · 繁體中文輕量排盤與 13 維詳批系統

這是一套免費、開源、全繁體中文的紫微斗數排盤網站（倪海廈《天紀》體系）。輸入出生年月日時，瀏覽器馬上排出十二宮命盤，同時直接調出 1950–2026 年共 67.5 萬張命盤的 13 維度完整文字詳批（每張盤約 3 萬字），不用花錢買點數，也不用綁任何 AI Key。

---

## 1. 這套是從哪來的？

本專案改寫自 [Renhuai123/ziwei-doushu](https://github.com/Renhuai123/ziwei-doushu)（作者：王多鱼AI）。

原作者開源了寫得很紮實的倪海廈《天紀》排盤核心（真太陽時、中國夏令時、四種閏月口徑、星曜亮度流派、1100+ 行格局判定、古籍原文），也釋出了一份「v4.0 13 維解讀資料集」（涵蓋 1950–2026 年每個真實日期 × 12 時辰 × 男女，共 674,976 張命盤）。

但原版倉庫有幾個很痛的地方：
- **資料集解開高達 56.6 GB**：原版把 67.5 萬張命盤的斷語全部攤平成 77 個巨型 JSONL 文字檔，一解壓就吃掉五十幾 GB 硬碟，而且開源版前端根本沒有寫讀取這份資料集的介面。
- **全站簡體中文**：介面、古籍與斷語皆為簡體。
- **功能半套**：原版留了歷史紀錄與分享卡元件卻沒接進頁面，也沒有跨裝置儲存案件與 AI 解讀後端。

所以我把這些缺口全部補齊，重新打包成這個可直接自架使用的版本。

---

## 2. 為什麼可以把 56.6 GB 縮到 167 MB？（空間省 99.7%）

原版那 56.6 GB 的斷語其實是確定性規則拼出來的。實測拆解單年 742 MB 的資料後發現，裡面超過 **99.3% 的文字都是跨命盤重複出現的固定斷語與古籍引文**，真正不重複的句子一年只有約 3 萬條（不到 5 MB）。

我們直接用 Node 22 內建的 `node:sqlite` 與 `node:zlib`（零外部套件依賴）重寫了底層儲存與讀取引擎（`lib/ziwei-dataset.ts` 與 `scripts/build-dataset-db.mjs`）：

| 儲存方式 | 77 年全量體積 (1950–2026) | 單盤讀取速度 | 說明 |
|---|---:|---:|---|
| 原版平鋪 `year-*.jsonl` | **56.6 GB** | ~5,350 ms | 硬碟直接塞爆，查一盤要掃幾百 MB |
| **本版 `ziwei-v4.sqlite`（預設）** | **167 MiB** | **0.4 ms（快取）/ 65 ms（冷讀）** | 抽離唯一句子字典＋`Uint16` 行索引＋月區塊 Zstd 壓縮，100% 逐字無損還原 |
| **本版 `.zst` 即時串流解壓** | **160 MiB** | ~2,500 ms | 不轉 DB 也能直接串流解壓原版 `year-*.jsonl.zst`，讀到目標盤立即中止 |

原本要吃 56.6 GB 的資料，現在**單一顆 167 MiB 的 SQLite 檔案就裝完 674,976 張命盤 × 13 維度（877 萬段解讀）**，排盤頁面右上角還可以直接切換 `SQLite` 與 `.zst直讀` 測試解壓速度。

## 3. 免費排命盤＋完整功能（免 API Key）

不需要接任何付費 AI，克隆下來就能免費使用完整功能：

- **免費即時排盤**：支援公曆／農曆、真太陽時經度校正、早晚子時換日、本命／大限／流年切換、四化飛星提示。
- **13 維典籍詳批秒出**：涵蓋命格、性格、感情、事業、財運、健康、兄弟、子女、遷移、人際、田宅、福德、父母共 13 個維度。點選左側命盤任一宮位，右側自動跳轉對應詳批。
- **三種命盤保存方式**：
  1. **儲存為案件（伺服器端 `/api/cases`）**：可加備註（例如客戶名稱或諮詢重點），存在伺服器 JSON，換電腦或手機也能調閱。
  2. **最近排盤（瀏覽器 `localStorage`）**：自動記住最近 10 筆排盤。
  3. **下載命盤圖**：一鍵匯出高解析度繁體命盤分享卡 PNG。
- **古籍全文檢索與百科**：內建《骨髓賦》、《紫微斗數全集》、《紫微斗數全書》閱讀器與搜尋。
- **可選 AI 互動追問（RAG）**：如果你有 OpenAI 相容的 API Key（OpenAI / DeepSeek / GLM 等），填進 `.env.local` 後就能開啟「AI 互動解讀」與合盤分析；後端會自動把該命盤的 v4.0 斷語塞進 Prompt 當作依據，不怕 AI 亂掰。

## 4. 全站繁體中文

針對台灣與繁體中文使用者：
- 內建 `components/Traditionalizer.tsx`（基於 `opencc-js` 簡轉繁台灣詞庫），在畫面渲染與動態載入時即時轉換所有文字、13 維斷語、古籍與 AI 串流回應。
- 內部排盤演算法維持原星曜鍵值，不會因為簡繁轉換弄壞查表邏輯；匯出的 PNG 命盤圖片也同樣是繁體中文。

## 快速開始

環境需求：**Node.js 22+**（使用了 Node 22 內建的 `node:sqlite` 與 `node:zlib` Zstd 支援）及系統 `zstd` 指令。

```bash
git clone https://github.com/thx0701/ziwei-doushu.git
cd ziwei-doushu
npm install

# 複製環境變數範本（只用免費排盤與 13 維詳批可不填 AI Key）
cp .env.example .env.local

# 啟動開發伺服器
npm run dev
```

### 13 維斷語資料庫（已內建於 `data/`，免額外下載）

倉庫內的 `data/ziwei-v4.sqlite.part-a*`（4 個 45 MB 分片，避開 GitHub 單檔 100 MB 限制）已經包含完整 77 年（1950–2026）的壓縮資料庫。第一次查詢時，系統會在 0.5 秒內自動合併出 `data/ziwei-v4.sqlite`（167 MiB），開箱即用。

如果你想從上游 [Release v4.0-13d](https://github.com/Renhuai123/ziwei-doushu/releases/tag/v4.0-13d) 的 `year-*.jsonl.zst` 重新自行壓製，也可以跑：
```bash
node --no-warnings scripts/build-dataset-db.mjs data/ziwei-v4.sqlite 1950 2026 4 9
```

### 測試與建置

```bash
npm run typecheck   # TypeScript 型別檢查
npm test            # 排盤鐵律回歸測試 + SQLite/.zst 13 維逐字無損一致性測試
npm run build       # 正式環境編譯
npm start
```
